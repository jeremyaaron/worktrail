Connected work

From the daily queue to delivery evidence.

01

Find the next action

Start with relevant work, not a search through every project.

  • My Work and Inbox bring assignments, mentions and watched updates together.
  • Share applied filters and return to saved or pinned views.
  • Quick Find keeps successive inspections moving with refreshed results.
02

Shape and deliver work

Keep execution and its supporting context in one place.

  • Operate project lists and boards with durable ordering and scoped triage.
  • Break outcomes into direct child work; track dependencies separately.
  • Read requirements, discussion and attached files before opening an editor.
03

Plan and review delivery

See delivery pressure and make scope decisions deliberately.

  • Compare project health, planning context and report freshness in Portfolio.
  • Review live milestone and cycle scope with actionable risk links.
  • Choose where unfinished work goes and inspect the complete outcome at close.
04

Explain decisions and share status

Keep current discussion distinct from published evidence.

  • Write formatted descriptions and comments with explicit mention recipients.
  • Protect authored drafts when leaving an editor or changing actor.
  • Publish frozen report snapshots and share reports or cycle outcomes as Markdown or print.

Run locally. Know the boundaries.

Local identity

No hosted service or production authentication. Actor selection demonstrates roles; it is not a secure identity system.

One local API instance

Compiled preview is for inspection, not internet-safe hosting. Files require persistent local disk; managed cloud deployment is not included.

Bounded capabilities

Search, authored content, files and synchronous data flows have limits. Attachments are not malware-scanned; signature checks do not establish file safety.

Try the reference app

A fresh local development setup.

Requires Git, Node 24, npm 11 and Docker with Compose. The Node commands below use nvm; another Node version manager works too. Choose a fresh demo database, not existing working data.

git clone https://github.com/jeremyaaron/worktrail.git
cd worktrail
nvm install
nvm use
npm ci
export NODE_ENV=development
export API_PORT=3000
export CORS_ORIGIN=http://localhost:4200
export WORKTRAIL_SERVE_STATIC=false
export DATABASE_URL=postgres://worktrail:worktrail@localhost:5432/worktrail
export WORKTRAIL_ATTACHMENT_STORAGE_DRIVER=local
export WORKTRAIL_ATTACHMENT_STORAGE_PATH="$PWD/.worktrail/attachments"
npm run db:start
npm run db:migrate
npm run db:seed
npm run dev

Open http://localhost:4200. The API uses port 3000; Docker PostgreSQL uses 5432. If PostgreSQL already occupies 5432, follow the existing-server guidance in the README instead of starting the container.

For compiled assets, use the independent compiled-preview setup at http://localhost:3000. It establishes its attachment root before seeding, not after.
